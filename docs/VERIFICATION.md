## Исправления после повторного аудита

1. Некорректный абсолютный URL раньше превращался в необработанную ошибку URL-парсера и HTTP 500; теперь возвращается `400 INVALID_URL`.
2. Нулевой символ в названии мог пройти JavaScript-проверку длины, но нарушить SQLite CHECK и привести к 500; теперь текстовые поля отклоняют NUL с HTTP 422.
3. Сетевой smoke-тест использовал случайный номер порта, который мог оказаться занят; теперь ОС назначает свободный порт через `PORT=0`, а тест читает фактический адрес из вывода сервера.
4. Конкурентные тесты ожидают завершения workers, прежде чем проверять файл и выполнять очистку.

Первые два дефекта подтверждены падающими регрессионными тестами до исправления и прошедшими тестами после него.

| Реальный запуск `npm run test:network` | Заблокирован средой: `listen EPERM: operation not permitted 127.0.0.1` |
| Docker build и работа контейнера | Нет доступа к Docker daemon, не выполнены |
| Статическая проверка TypeScript | tsc недоступен; выполнение TypeScript и тестов не равно проверке типов |
| GitHub Actions | Настроены Node 24/26, TCP smoke и Docker Compose; удалённый запуск не выполнялся |

Перед отправкой работодателю нужен сетевой прогон на обычной машине или успешный запуск CI. Он не скрыт автоматическим skip и не отмечен как успешный в этом отчёте.

```sh
npm test
npm run test:network
docker compose up --build
```

Последняя команда необязательна для основного запуска по ТЗ, но необходима, если сдача предполагает именно Docker. После запуска контейнера `/health` должен возвращать `200` и `{"status":"ok"}`; процесс проверки контейнера также включён в GitHub Actions.
